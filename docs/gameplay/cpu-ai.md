# CPU

單人模式的對手。主要程式：[`sim/cpu.ts`](../../src/sim/cpu.ts)。

## 它為什麼住在模擬裡

CPU 產生的是**按鍵**，跟人類玩家一模一樣。它不是特權角色，不會直接寫狀態，走的是同一條 `stepFighter` 路徑。

因為它在 `src/sim` 底下，它必須遵守同樣的純淨規則 — 這帶來一個具體好處：**1P 對戰可以完全重播**。原本的 CPU 有七處 `Math.random()`；現在每一處都是從 `SimWorld` 裡那顆 seeded 產生器抽的，所以一場 1P 比賽能被壓成 golden replay 當作回歸測試。

## 決策節奏

CPU 不是每 tick 重新想一次。它做一個決定，然後**按住那個決定一段隨機時間**，才再想下一次。

那段時間就是難度最大的差異來源：

| | easy | normal | hard |
|---|---|---|---|
| 決策間隔 | 430–560 ms | 280–360 ms | 165–225 ms |
| 防禦機率 | 0.20 | 0.40 | 0.60 |
| 特殊技機率 | 0.15 | 0.32 | 0.45 |
| 重擊機率 | 0.18 | 0.30 | 0.38 |
| 跳躍機率 | 0.08 | 0.13 | 0.18 |
| 賭滿蓄機率 | 0（從不） | 0.30 | 0.50 |
| 蓄力長度 | 20–30 tick | 26–44 | 30–62 |
| 蹲防機率 | 0.15 | 0.30 | 0.45 |

## 兩個調整過的旋鈕，值得說明

**蹲防機率是猜，永遠不是讀。** 讓 CPU 去讀對方這一招的高度，會讓它對高低混合完全免疫 — 那不是把難度調緊，那是把一個互動整個拿掉。難度買到的是「猜得比較接近五五波」：easy 幾乎永遠站防，所以每一記下段都吃滿；hard 會把防禦分散，於是你真的必須混淆它。

**賭滿蓄的機率是從「永遠滿蓄」調下來的。** 滿蓄很貴 — 角色要站著不動將近一秒，而且期間不能防禦。原本 hard 有三分之二的比賽都在蓄力，結果它變得**更好打**而不是更難打。

## 決策順序

大致的優先序（[`cpu.ts` 的 `decide`](../../src/sim/cpu.ts)）：

```
1. 對手正在攻擊且距離內 → 依 blockChance 防禦
                            （並依 crouchBlockChance 決定站或蹲）
2. MEME = 100 且距離 < 560 → 大招（70% 機率）
3. 特殊技距離合適 → 按住特殊鍵蓄力
                     （長度依 chargeCommitChance 決定是輕點還是賭滿）
4. 近距離 → 輕重攻擊
5. 否則 → 朝理想距離移動，偶爾跳
```

大招用的是**大招鍵本身**，不是模擬人類的「按住 → 放開 → 再按」協議。交付說明明確指出這一點：能量條的按鍵協議是給玩家的輸入協議，不是給 CPU 的；兩者從那之後走同一套 cut-in 與大招流程。

## 已知的不足

upgraded build 的每個角色帶著**八個 CPU 偏好值** — 理想距離、侵略性、後退、彈道、投技、招架、護甲、大招。

這裡的 CPU 只讀難度 + 一個射程屬性。結果是**它把每個角色都打得差不多**。這是 README「Not ported」清單上的一項，還沒補。

## 訓練模式

`training` 是 `pvp` 但第二個座位放空、時鐘由玩家控制。它是一個**模式**而不是一個場景 — 比賽本身完全相同，另開一個 BattleScene 只會讓兩者漂移。

`F3` 凍結、`F4` 前進一格、`F5` 重置回合、`F6` 讓木樁按住防禦。回合永遠不會結束，該結束時就重來。
