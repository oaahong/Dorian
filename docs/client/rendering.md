# 渲染層

`src/render/` 讀 `SimWorld`，擁有每一個 Phaser 物件，**從不寫回模擬**。這條線的理由在 [架構總覽](../architecture.md)。

## 分工

```
BattleView                 收 SimEvent，翻成聲音、火花、播報
 ├─ FighterView × 2        角色貼圖、姿勢、變身放大、武器掛點
 ├─ CombatView             彈丸、領域、光束、召喚物
 ├─ UltimateStage          大招的美術拍點
 ├─ UltimateCutIn          大招開場演出
 ├─ VFXManager             火花、震波、殘影、閃光、震動
 ├─ AudioManager           即時合成的音效
 └─ BattleHUD              血條、能量、計時
```

## 兩種資料來源，用途不同

**事件（`SimEvent[]`）**：這一 tick **發生了什麼**。命中、起手、回合開始、彈丸生成。用於一次性的反應 — 播一個音效、噴一次火花。

**世界（`SimWorld`）**：現在**是什麼樣子**。位置、狀態、HP、存活中的實體。用於每影格的同步。

**召喚物刻意用世界對帳而不是用事件。** 九隻分身同一 tick 一起出現，然後被一個一個打掉；某個 id 這一影格**不在了**，就是 sprite 該被銷毀的全部訊號。用生成／死亡事件的話，等於要多維護兩樣東西去跟一個本來就在手邊的清單保持同步。

## 純函式住在哪

表現層裡凡是「要決定」的邏輯，都被抽成不 import Phaser 的純函式，因此能在 `environment: 'node'` 下測：

| 純函式 | 決定什麼 |
|---|---|
| `FighterView.artFor()` | 這個角色現在該畫哪張圖 |
| `ultimateSchedule.beatsBetween()` | 這一影格該放哪些大招拍點 |
| `effectCells.effectCellFor()` | 蓄力第 N 段用哪張圖 |
| `summonArt.summonCellFor()` | 召喚物現在該是哪個姿勢 |

Phaser 那一側只剩下「把結果畫出來」。

## `artFor` 的分支順序承重

```
1. 蓄力中          → 該等級的前搖圖
2. 蓄力技出招中     → 釋放圖
3. 變身中          → 變身姿勢表（查不到就落回一般圖）
4. ULTIMATE 狀態   → 大招本體圖
5. 其他            → 一般姿勢表
```

**第 3 步必須在第 4 步之前。** 變身在時間軸頂點生效（doge 第 54 tick），而 `ULTIMATE` 狀態要到第 64 tick 才結束 — 中間 10 tick 兩者同時成立。先讀大招的話，「宣告變身」那一拍之後角色還會維持變身前的樣子六分之一秒，而那正是變身唯一需要被看懂的時刻。

## 影格與 tick 不是同一個時鐘

`render()` **每影格**呼叫一次，但大招腳本是以 **tick** 撰寫。固定步長迴圈在客戶端落後時會一影格跑好幾 tick，所以：

**用相等比對會漏掉拍點，而且只在慢機器上漏。** `beatsBetween(script, 上次播到, 現在)` 取的是這一影格實際涵蓋的區間，把裡面全部補放。

`UltimateCutIn` 是同一個問題的另一個解法：它跟著**模擬自己的凍結倒數**推進，而不是自己開一個計時器。

## 尺寸靠 fit，不靠 scale

每一張圖來自不同的管線，框法都不一樣 — 圖格從 88×226 到 363×169 都有。給固定 scale 會讓某些角色是別人的兩倍大。

所以一律 [`fit.ts`](../../src/render/fit.ts)：縮到指定高度，不管來源解析度。`FighterView` 更進一步用「尺寸類別」（`fighter` / `downed` / `ultimate`）把不同圖表拉到同一個視覺大小。

## 缺圖的處理原則不一致，而且是刻意的

| 情況 | 缺圖時 | 為什麼 |
|---|---|---|
| 召喚物 | 畫一個**洋紅色方塊** | 它有判定框。看不見的東西在打人，是這裡最糟的失敗 |
| 大招拍點 | **跳過** | 純裝飾。畫不出來不如不畫 |
| 蓄力特效 | 退回純色形狀 | 有既有的表現方式可用 |

## 表現層可以隨便亂來

閒置時的呼吸擺動、落地的擠壓、殘影、螢幕震動 — 全部讀牆上時鐘、用 tween、用 `Math.random()`。

**這在這一側完全沒問題**，因為它們永遠不寫回模擬。那正是這個切分存在的理由。
