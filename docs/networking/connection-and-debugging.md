# 連線建立與除錯

從按下 `ONLINE VS` 到兩個人在打，中間發生什麼；以及不順時怎麼看。

## 玩家看到的流程

```
一方                              另一方
ONLINE VS                        ONLINE VS
 └─ F 建房                        └─ J 加入
     └─ 拿到六碼房號 ──── 唸給對方 ──> 輸入房號
          └─ 兩邊選角、按準備
               └─ 伺服器送出 matchStart（種子、場地、輸入延遲）
                    └─ 嘗試直連 ── 失敗 ──> 中繼後備
                         └─ PrepareMatchScene（兩邊等較慢的那個）
                              └─ 開打
```

大廳會顯示最後拿到的是**直連**還是**中繼**。

## 房號

六碼，字母表在 [`roomCode.ts`](../../src/net/roomCode.ts)，客戶端與伺服器共用。

**`0`/`O` 與 `1`/`I`/`L` 被排除**，因為房號是用唸的 — 兩個人在講電話或坐在旁邊。

字母表放在共用處是因為大廳也要用它過濾輸入：打錯的字在按鍵當下就被拒絕，而不是等一下變成一次失敗的加入。

## NAT 穿透

用**公開 STUN**。行不通時，那條為了大廳而已經連著的 socket 接手中繼。

所以沒有 TURN 伺服器要付錢，也沒有「連不上」這個終局狀態 — 最壞情況是比較高的延遲。

## `F2` 除錯面板

```text
NET ok delay=4 stalled=0
FPS 60.0  TPS 60.0  TICK 431  PHASE fight
```

| 欄位 | 意義 |
|---|---|
| `NET` | `ok` / `waiting` / `desync` / `disconnected` |
| `delay` | 議定的輸入延遲（tick） |
| `stalled` | 累計等待對手的 tick 數 |
| `FPS` | 繪製速率 |
| `TPS` | **模擬速率 — 連線時真正重要的那個** |
| `TICK` | 目前 tick |
| `PHASE` | `intro` / `fight` / `ending` |

### 怎麼讀

**健康的比賽是 `NET ok` 加 `TPS 60`。**

| 症狀 | 意義 |
|---|---|
| `TPS 60`、`FPS` 低 | **不是連線問題。** 這台機器繪製慢但模擬完美，對手不受影響 |
| `NET waiting`、`stalled` 一直漲 | 在等對手的輸入。對方的連線或機器跟不上 |
| `NET desync` | 兩邊的世界已經分歧。回報而不是假裝沒事 |
| `NET disconnected` | 連線斷了 |

**`TPS` 才是重要的數字，不是 `FPS`。** 一個客戶端可以用 16 fps 繪製並完美模擬 60 tick/秒 — 固定步長累加器一影格會跑好幾 tick。一場被連線拖住的比賽在 `FPS` 上看起來很健康，卻不能玩。

## 常見狀況

**「很卡」但 `TPS` 是 60。** 那是繪製，不是網路。關掉其他分頁。

**兩邊都在 `waiting`。** 通常是輸入延遲或傳輸不一致 — 兩者都會造成雙方各自等一格對方永遠不會送的輸入。它們在大廳議定，所以這通常代表有一邊是舊版客戶端。

**開場就永久卡住。** 同上。開打幾 tick 後發生，症狀與斷線無法區分。

**`desync` 出現在某個特定招式之後。** 那是模擬層的 bug，不是網路層的。找 `src/sim` 裡新加的東西有沒有讀了時鐘、用了 `Math.random`，或把狀態放在 `SimWorld` 之外。[`purity.test.ts`](../../src/sim/__tests__/purity.test.ts) 擋掉大部分這類問題，但擋不掉「狀態放在模組層級變數裡」的所有變體。

## 暫停在連線時的行為不同

`Esc` 在離線時是暫停。**連線時是離開比賽** — 因為暫停會讓對手無限期卡住。
